# 回复状态整组动效打磨

用户反馈上一版文字流光偏淡、右侧三个点静止，而且正文开始输出后左侧光带消失。本轮以整组动效的连续性为目标，替代此前「首段出现后收起左侧光带」的设计。

## 最终行为

| 部分 | 实现 |
| --- | --- |
| 左侧光带 | 保留原形态和尺寸；等待、思考、正文输出阶段均持续运动 |
| 文字 | 蓝灰底色，青蓝、银蓝、紫色高光扫过；高光带由文字宽度的 90% 增至 120%，加强可见度 |
| 三个点 | 原生内联圆点，依次上浮、增亮、微增大再落回；每个点错开约 196 ms，最大上浮约 3.4 sp |
| 统一节奏 | 共用 2,800 ms 时间轴，三点每个主循环完成两次波动；不因正文更新重启 |
| 正常结束 | 整组继续运动并在 180 ms 内淡出收起，无单独消失的光带或静态尾巴 |
| 停止中 | 保留整组，文字变为「正在停止…」，冻结当前画面 |
| 后台/离屏/关闭动画 | 停止循环，保留当前相位；可继续时接续，不跳回起点 |
| 无障碍与字号 | 保留完整文字「正在回复…」；三个装饰点不独立播报，随系统字体放大 |

修改范围是 `ReplyProgress`、`ConversationContent` 的状态行及相关测试。移除不再需要的首段正文识别状态、辅助函数和专用单测，没有引入新依赖或改动接口。绘制阶段读取时间轴，缓存画刷与路径，避免逐帧正文排版。

## 验证

- 35 项 JVM 测试通过；Debug 和 AndroidTest 构建通过。
- 12 项不同的模拟器 UI 用例最终通过：文字、三个点、光带各自有像素变化，正文出现后光带继续显示和运动；停止、审批、断连、恢复、补历史、下一轮、关闭动画、离屏结束、滚动锚点、6 组屏宽/字号、隔离网关完整页面和平台实际时间轴均覆盖。
- 首轮 11 项回归中，暂停帧测试 1 项失败：暂停状态在下一次重组生效，时钟可能先走一帧。断言修正为比较暂停画面仍接近暂停前而非初始相位，并验证此后完全静止；该项与平台时钟用例复跑通过。
- 原生平台播放覆盖多个循环、首段出现、三次正文追加和最终整组移除；独立录屏检查了高光扫过、点的错峰起伏、文字位置以及正文期间光带保留。
- 最后一次未同时录屏/截图干扰的 6 秒采样为 360 帧，窗口 TOTAL_DURATION 的 P95 为 32.35 ms、超过 32 ms 共 21 帧。该指标仍受模拟器与宿主机影响，不能据此保证真机 60 fps；原始日志保留在 `metrics-final.log`。
- 恢复真实应用后，原保存端点 `10.0.2.2:58901` 的健康检查、消息、子代理读取均为 200，WebSocket 为 101，当前页面没有连接错误提示。此检查与隔离组件实录分开进行。
