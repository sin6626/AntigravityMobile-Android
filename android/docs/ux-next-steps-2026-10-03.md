## 第一批：聊天操作补齐

| 建议 | 当前代码证据 | 最小实现与验收 |
| --- | --- | --- |
| 停止生成 | Composer 只有发送按钮，`isRunning` 没有传入；ApiClient 已有 `cancelInvocation` / `stopTask`，ChatViewModel 未调用 | 运行中提供停止入口，区分发送请求中与 Agent 运行中；提交停止时防重复，失败可再试，成功后按服务端状态收敛。停止整轮与停止后台命令的语义须先核对，不能承诺停止生成一定终止所有命令 |
| 真正的“更多”菜单 | ChatDemoScreen 的 `onMore` 直接打开删除确认；ConversationTopBar 没显示当前会话标题 | 更多菜单先只含重命名、删除；允许识别当前会话，删除仍需确认。重命名失败保留旧标题，返回列表与重新拉取后标题一致 |
| 按会话保存草稿 | ChatUiState 只有一个全局 draft / attachments；openConversation 不切换草稿；PreferencesManager 已有草稿方法，当前 ViewModel 没接入 | 先复用现有文字草稿存储，隔离 A/B 会话与新聊天；切换后各自恢复，进程重启也能恢复文字。图片恢复另行核对持久 URI/缓存与清理策略，不顺带重写缓存系统 |

**重命名不是直接接现有方法就能结束。** Android `ApiClient.renameConversation` 使用 `SetCascadeTrajectoryMetadata` 和单个 `cascadeId`；Web 使用 `UpdateConversationAnnotations`，传 `cascadeIds`、`annotations`、`mergeAnnotations`，网关对后者有专用标题缓存处理。实施前先核实并统一现有协议，再做 UI 与持久化验收。本次未调用上述接口。

## 第二批：阅读与恢复体验

| 建议 | 当前代码证据 | 最小实现与验收 |
| --- | --- | --- |
| 回到最新消息 | ConversationContent 已判断 nearBottom / followLatest，历史阅读会暂停跟随；没有主动返回末尾的按钮 | 离开末尾时出现一个回到最新入口；阅读旧内容时新消息不抢位置，点击才回末尾，发送仍按现有行为定位。先不做未读条数统计 |
| 断线与重试 | StreamWebSocketClient 已有连接状态和自动重连，但 ChatUiState 没暴露；错误集中显示 Snackbar 后清除 | 复用连接状态，区分正在回复、等待用户、正在重连、读取失败；失败页保留重试入口，保留已读内容。重连后同步当前会话，不能将断线误报为任务已停止 |
| 图片预览 | MessageImages 大图只有 Fit 与点击关闭，没有缩放/拖动或重试；LinkedFilePreview 的图片已有重试 | 先补聊天图片失败重试和明确关闭入口，再加双指缩放/拖动；放大查看 UI 截图后不误触关闭。文档内图片的查看入口一起核对，保留现有鉴权与原图接口 |
| 搜索与列表反馈 | 抽屉只过滤已取得的项目名/会话标题，无正文搜索；空结果仍显示暂无会话；抽屉使用 verticalScroll + forEach，项目展开一次组合所有子会话 | 先完善无匹配结果、清空搜索、当前会话选中态；项目 key 目前含 index，刷新重排时需要保持展开身份。大量会话是否改懒列表以实际规模/测量为依据，不直接宣称已卡顿 |

还应覆盖异步操作时切换会话：删除成功会直接 newConversation，交互提交成功会直接清 pendingInteraction，失败发送会恢复到当前全局草稿。存在跨会话状态写入风险，需以捕获的会话 ID 和可取消任务核查并复现；本次不将这些静态风险描述为已发生的真机故障。

## 第三批：让状态变化更自然

1. **界面切换**：目前首页/项目列表与会话用条件分支直接替换。对进入会话、项目返回、新建聊天加短过渡，保证草稿、键盘与滚动位置保持原有语义。不要同时组合两个完整富文本会话以做交叉淡入。
2. **输入栏与键盘**：保留现有单一 BasicTextField、IME Insets 与弹簧；核对多行输入、4 张附件、快速开合键盘、连续移除附件时高度是否跳动。附件删除、发送/停止按钮状态切换做短反馈；先补状态，再统一节奏。
3. **流式结束**：现在增长正文用普通 Text，完成后切原生 Markdown。以包含标题、代码和表格的真实回复检查切换是否突变；优先减少高度与锚点变化，再考虑短淡入。不对每个历史 Markdown 块增加入场动画。
4. **执行过程**：已有 220 ms 顶部展开动画和分帧坐标测试，保留它。新增动效不能重新引入反向列表或逐帧滚动补偿；不要让运行状态变化触发整个过程列表重组。
5. **触达与无障碍**：部分加号/麦克风/附件删除仅按图标尺寸点击，缺少独立描述。扩大点击区域而不改变图标视觉尺寸，补描述与忙碌状态；可选轻触反馈，避免为每次流式更新震动。现有流式文字读取系统动画开关，应继续保留并检查关闭动画时所有新增效果的行为。

验收关注结果：中途反向操作不跳位、历史分页不抢阅读位置、键盘返回不退出会话、图片可看清、关闭系统动画仍正常。录屏逐帧检查布局，再在 USB 真机复测长消息快滑；此前性能数据不能代表加入高亮或新动画后的性能。
