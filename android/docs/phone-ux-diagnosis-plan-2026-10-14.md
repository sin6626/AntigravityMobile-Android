## 实施顺序和提交边界

### 1. 修复图片发送后的即时显示

建议提交：`fix(android): 即时显示本地发送图片`。

- 复用消息模型已有 `effectiveImageDataList` 和现有图片组件，统一本地字节、服务器缩略图和原图 URI 的选择规则。
- 点击发送后立刻在本地用户消息中显示图片，可放大；网络请求还在进行、服务器只返回文字或 WebSocket 重连时，预览持续保留。
- 服务器确认后合并为同一条消息，原图可用后接替本地预览；确认逻辑继续要求新消息身份、步骤范围与附件，不因为相同文字把另一条图片消息误删。
- 运行中排队也保留本地图片预览和“正在加入队列”反馈；服务器队列到达时按实际可验证标识合并。没有可关联标识时先核契约，不能用文本相同就删除占位。
- 发送失败沿用既有草稿恢复；退出/回到会话和进程恢复不得提前清理仍被引用的私有图片。发送成功而服务器图片稍晚可用的衔接需要覆盖，避免闪空或重复。

涉及 `ChatImage`、`StreamPayload`、`ChatViewModel.send/queueCurrentMessage/reconcileOutgoing`、队列面板、草稿存储生命周期及图片/发送测试。

验收：1 张与 4 张、只有图片与图片加文字、慢响应、文本先到附件后到、重连、重复快照、同文多次发送、失败恢复、运行中排队。首个本地状态即可见图片；不等待服务器回传，不产生重复消息。不能通过真实用户会话写入完成验收，应使用隔离测试会话。

### 2. 修复输入框工具栏的空间分配

建议提交：`fix(android): 保证输入框操作按钮尺寸`。

- 先保留加号、语音、发送的固定触控空间，模型名称和工作方式使用剩余空间。长名称省略但可点击打开完整模型列表，不缩小整页字号。
- 运行中需要同时出现停止和排队发送时，将两枚动作按钮一并纳入宽度预算。极窄布局把次要设置挪入现有操作面板，主要动作始终可见。
- 发送可视圆为 44 dp，触控区至少 48×48 dp；不能仅强制绘制尺寸后让按钮溢出父容器。
- 静止、展开中、收起中、快速反向、语音错误条出现及排队动作出现时都维持圆形，没有重叠或裁切。

涉及 `ComposerActions`、`SendAction`、模型/工作方式标签与调用方、`MotionTest`、`ReducedMotionTest` 及窄屏测试。

验收：上述 12 种宽度/字号组合加字体 1.5、实际真机配置；完整真实模型名称；普通发送、排队、停止三种状态。逐帧检查按钮宽高，主按钮不得消失。先让 51×126 px 的失败用例转为正常，再调整动画。

### 3. 打磨输入框与键盘开合动画

建议提交：`fix(android): 平滑输入框与键盘开合过渡`。

目标是达到 Web Motion 常见布局动画的连续感，使用已有 Compose 原生能力；没有必要给 Android 引入 Web 动画运行时。

- 将收起/展开的容器高度、圆角、字段位置和工具位置交给同一个布局过渡协调，字段仍只保留一份，避免双输入框导致光标或焦点丢失。
- 主按钮采用稳定尺寸，只改变位置和必要透明度；容器变化不缩放文字、图标或圆形按钮。
- 动画暂以约 220 ms、无弹跳的自然减速为试调起点，最终参数按逐帧与真机观感确定，不能只把旧时长加长。
- 快速聚焦→返回→再次聚焦从当前动画进度继续，不回到起点；退出中的控件立即失去点击语义。
- IME Insets 跟随系统键盘，不额外叠加一套延迟位移；避让、聊天底部留白和返回最新按钮同步，阅读历史时不抢滚动位置。
- 减少动态效果时直接到最终布局，保留阴影与状态反馈。

涉及 `Composer`、`ChatDemoScreen` 的焦点/IME 与布局尺寸回报、聊天底部留白、模型选择后的聚焦，以及现有逐帧测试。先复用现有 transition/spring 和布局测量，不预设新的动画框架。

验收：真机原输入法、系统输入法与模拟器分别录制开/关/快速反向；0～4 行、0～4 张图片、语音条出现/消失、模型面板关闭后恢复焦点、系统返回键、字体放大。逐帧无按钮拉伸、字段跳位、阴影消失和键盘后的额外位移。静态截图不能代替动画验收；没有真机帧数据不能宣称性能改善。

### 4. 整理无网与网关断连界面

建议提交：`fix(android): 统一聊天断连与重试反馈`。

- 保留用户认可的骨架屏构图。首载无缓存时继续使用现有骨架；长期断连时显示诚实的连接提示，避免骨架和旋转按钮一直暗示“仍在成功加载”。已有聊天保留正文和阅读位置。
- 统一使用一条紧凑的连接提示，轻背景、正文颜色的简明标题和单个“重试”操作。例如无网络为“暂无网络连接”，HTTP 530 为“暂时连接不上电脑网关”。技术码进入脱敏日志，主界面不堆 HTTP 数字和大段红字。
- 无子代理数据、首次读取失败时，不弹出“0 个子代理”的独立大卡片；已有子代理数据则保留旧列表并标注尚未同步。真正的单功能失败仍有对应重试，不能全部隐藏。
- 将历史加载、草稿恢复、回退、队列忙碌与真实发送状态分开传入 Composer。没有发消息时不显示“正在发送”；断连可以编辑和保存草稿，不新增自动重放写请求。
- 复用 `ConnectionManager` 与 WebSocket 重连状态；整体断连时子代理轮询暂停或退避，避免每 3 秒产生同一种错误。手动重试和网络恢复共用已有恢复入口，不并发启动多条重连链路。
- 401 仍进入正确的配对失效流程，不能替换成普通“没网”提示。提示出现/恢复用克制的淡入和尺寸过渡，不反复顶动输入框。

涉及 `ChatDemoScreen`、`ChatUiState/ChatViewModel`、`SubagentsPanel`、`ConnectionManager`、接口失败分类与 `ApiTraceInterceptor`、骨架和错误重试测试。请求、脱敏头、状态、响应继续记录，附件正文和令牌保持隐藏。

验收：断网首载、已有缓存断网、HTTP 530/502、超时、TLS/DNS 故障、401、单独子代理请求失败、手动重试、自动恢复、恢复期间重复点击、切会话。只有一条整体连接提示；未知子代理数量不写成 0；缓存、文字、图片与阅读锚点不丢。

### 5. 让语音输入在真实设备上可用

建议提交：`feat(android): 接入可用的原生语音输入`，具体识别来源需通过设备检查后确定。

当前结论是桌面账号拒绝了现有接口，手机麦克风录音和假网关成功不能证明真实语音可用。`voiceErrorMessage` 还把任意 `PermissionDenied` 归为账号未开放，需要按真实错误范围区分麦克风权限、识别服务权限、网关鉴权与上游 scopes。

实施前必须完成的来源检查：

1. 真机重新进入 ADB 后读取 SDK、`voice_recognition_service`、`RecognitionService` 服务清单。确认输入法自带语音入口是否对应公开可调用服务，不能依据键盘上有麦克风图标推断。
2. 做 Android 系统识别的最小真实探针，查可用性、中文支持和端侧模型状态；具备端侧中文能力时优先端侧识别，否则核查系统默认服务的实际成功路径。不得把“安装了服务”当作转写验收成功。
3. 若该真机没有可用系统服务且电脑仍拒绝现有接口，先确认后端语音来源及请求契约，再选择修复现有上游授权或独立的电脑转写服务。新服务须明确音频格式、时长/大小、流式结果、取消语义、语言、错误码和凭据来源；此时向用户列出具体缺失字段，不猜接口、不硬编码服务商密钥。

原生识别可行时复用现有语音条、计时、草稿合并与取消逻辑，界面状态区分准备、正在录音、整理文字、完成、可恢复错误。状态和动画必须跟实际回调一致。识别服务与 `AudioRecord` 不得同时抢麦克风；取消、切会话、退出后台及时停止并释放资源；失败恢复原文字和附件。日志只记录能力与错误类型，不打印录音和识别文字。

Android 11 及以上使用系统识别服务需要 Manifest 查询声明；对象必须在主线程创建/操作，不用时 `destroy()`。端侧识别 API 从 API 31 提供，API 26～30 和无端侧服务的设备需分开判断。具体 API 以 [Android SpeechRecognizer 官方文档](https://developer.android.com/reference/android/speech/SpeechRecognizer) 为准。

涉及 Manifest、`VoiceRecorder` 或实际原生识别适配、`ChatViewModel` 语音状态、Composer 入口/语音条与识别生命周期测试。如果选用新电脑语音服务，网关契约与 Android UI 分成两个提交。

验收门槛：这台真机说一段中文，实际得到可编辑文字，再测试停止、取消、权限拒绝、无声音、无网络、识别模型缺失和切会话。假网关用于错误/延迟回调回归，不能代替真实中文成功。未跨过此门槛，语音任务保持未完成。

## 对此前验收的修正

- 之前 Composer 组件测试多用默认参数，没有带真实工作方式、完整模型名称、右侧语音和发送组合，也没有覆盖多个屏宽/字体比例。后续测试需要覆盖实际调用配置。
- 之前图片测试覆盖服务器图片和图片查看器；`OutgoingMessageTest` 验证确认逻辑，但没有断言发送当下是否渲染本地图片。补“服务器尚无任何回复”的截图与节点断言。
- 之前语音验收只证明协议与状态机，已知真实账号 scopes 拒绝却仍被列为已完成。本计划将其恢复为“真实可用性待完成”。
