# 第三轮动效方案

日期：2026-10-04。代码基线：`4971328`。状态：方案已实施并通过模拟器技术验收，待用户体验反馈。

本文最初仅阅读源码与官方文档整理方案，未修改应用或操作设备。用户随后授权实施；第二轮尚未由用户亲自检查，不能把其技术验收写成用户已认可。以下保留设计依据和候选方案；实际实现与结果见 [第三轮验收记录](ux-round3-verification-2026-10-04.md)。

## 建议的观感

操作发生后立即反馈，内容在约 120–220ms 内平稳到位；拖动跟随手指，文字保持清楚，输入栏和阅读位置稳定。页面保持现有白、灰、蓝色和原有圆角，不增加素材需求。

优先处理输入栏和回复结束的布局变化，再补会话入口、附件和小型菜单的过渡。下面的时间与位移是本项目的候选值，需用正常速度录屏调整；静态参考截图无法证明原应用的动画参数，不能宣称已经还原其动效。

| 位置 | 当前实现 | 对第三轮的影响 |
| --- | --- | --- |

| 更多菜单 | 小型原生 Popup，显示时直接创建，关闭时直接移除 | 可以补短淡入与微缩放；出场需到动画结束再移除弹层，同时立即停止旧条目交互 |

## 动画选择

| 操作 | 建议效果 | 起始参数 | 保留条件 |
| --- | --- | --- | --- |
| 首页/项目/归档打开会话 | 目标内容轻微横向进入并淡入；顶部操作和输入栏保持位置 | 内容 8–12dp，160–200ms；大字体/减弱动画时仅淡入或直接显示 | 不叠着渲染两份完整富文本；消息首次定位完成后才显示，HTTP/WS 更新不重播 |
| 返回项目/归档 | 对应列表反方向轻微进入，恢复原列表位置 | 8–12dp，160–180ms | 系统返回仍先处理键盘、弹层、抽屉；列表展开和滚动状态不重置 |
| 新建聊天、普通会话之间切换 | 新内容短淡入，不用层级方向 | 120–160ms | 新建立即生效；草稿按现有语义切换，输入框不额外失焦 |
| 输入栏聚焦/失焦 | 宽度、圆角与操作行协调变化；输入框持续存在 | 复用现有 spring，先试无回弹；文字区按 1–4 行增长，单次高度变化约 180–220ms | 一个变化只由一个层级负责尺寸过渡；首要保证文本与光标可见 |
| 添加附件、删除最后一张附件 | 附件托盘展开/收起，图片短淡入 | 高度 180ms，图片淡入约 120ms | 点击添加立即进入系统选择器；返回后才展示附件，不拿动画延迟数据变化 |
| 连续删除中间附件 | 删除立即生效，其他缩略图平稳补位 | 原生重排约 160–180ms，若确有明显跳位才做 | 图片以 URI 保持身份；最多 4 张，优先原生 keyed LazyRow 的 animateItem，不手写删前数组和计时队列 |
| 发送→请求中→停止→完成 | 按钮大小、蓝色圆面和点击区域固定，只切换内部图标 | 保留现有 120ms Crossfade | 忙碌/禁用立刻生效，动画中的旧图标不能再次提交；失败恢复仍按真实状态执行 |
| 更多菜单 | 从更多按钮所在角轻微放大并淡入，关闭更短 | scale 0.96→1、alpha 0→1，进入 140–160ms，退出 100–120ms | 保留标题、置顶、归档、删除布局；焦点/返回/点击外部关闭正确，退出中不能再点击条目 |
| 项目或执行过程展开 | 标题固定，下方内容展开并淡入 | 项目 180–220ms；执行过程先保留现值 | 展开高度只由 AnimatedVisibility 负责，不在同一父级再套尺寸动画；阅读历史时不自动追到最新 |
| 本地新消息、复制、回到最新 | 保留现有短反馈 | 180ms / 原有对勾 / 120ms | 不增加整条回复入场、复制弹跳、按钮反复脉冲；大段跳转沿用列表原生滚动，不新增自制滚动轨迹 |

方向只用于有父子关系的“列表进入会话/返回列表”。抽屉选择另一个会话是同级切换，只淡入目标内容；从抽屉选中后不同时启动抽屉关闭与内容横移。第一页→项目页保留现有 Pager 跟手，不额外播放本表的会话过渡。

## 最先解决的两处

### 输入栏：让高度跟随内容

先录 1 行→4 行→删除至 1 行，核对当前 58dp 固定文字行是否造成裁切或内部滚动。若有问题，文字区改为适应行数的受限高度，保留同一个 BasicTextField、选区和输入法组合文本。不要拿上下浮动动画掩盖文字显示空间不足。

再统一附件托盘、操作行与父容器的高度变化：明确每一部分的尺寸负责人，减少父子同时插值造成的二次变化。宽度与圆角可继续使用现有弹簧，但先取无回弹候选；不新建动画配置框架。

键盘跟系统 IME Insets 的进度走。Compose Insets 本身同步键盘动画，内置 Modifier 在布局阶段读取 Insets；这是优先复用 imePadding、核查当前键盘高度读取方式的依据。不能同时再对 keyboardHeight、Composer 底部位移和消息底部留白做三次动画。[官方 Insets 文档](https://developer.android.com/develop/ui/compose/system/insets-ui)

### 回复结束：稳定排版与阅读锚点

测试样例包含纯文字、标题/列表、代码、表格、图片、公式/图表。分别比较流式末帧与最终 Markdown 首帧。

1. 比较字体、行高、首尾间距，先减少可避免的排版差异；保留已有顶层块懒加载、后台准备和末块 key。
2. 用户阅读历史时，保留可见消息/块及屏内偏移；数据完成后需要校正时只做事件级校正。不要为每一帧高度变化滚动补偿。
3. 用户停在底部时继续遵循现有跟随规则；拖动、展开执行过程后不能强制拉回底部。
4. Markdown 准备好后一次切换；正文清晰显示，不把整段透明度降到零，也不在结束后重新播放逐字出现。

如果代码/表格等复杂排版仍造成明显跳动，再评估局部格式化方式。当前没有录屏证据支持“每个 token 都解析并动画化 Markdown”，不在这次设计阶段预定渲染引擎重写。

## 实现边界

- 基础优先用现有 Compose animate*AsState、AnimatedVisibility、Crossfade 和原生 Pager。相关属性需要共用进度时再用 updateTransition；明确可取消的进入动效才用 Animatable，不建全局动画管理器。[官方 API 选择指南](https://developer.android.com/develop/ui/compose/animation/choose-api)
- 小组件可保留原生出场生命周期；聊天长内容优先单份目标内容加 graphicsLayer 的透明度/短位移，不对两份完整会话套 AnimatedContent/Crossfade。透明度为 0 不等于已从布局或无障碍树移除，交互/语义必须随实际可见状态处理。[官方动画指南](https://developer.android.com/develop/ui/compose/animation/quick-guide)
- 不延迟接口提交、退出导航或草稿保存来等待动画结束；快速返回、反向操作和 A→B→A 时，以最新真实状态为准，取消上一段视觉过渡。
- 动画关闭时，按钮仍可点、内容立即完整显示、回退与状态切换立即生效。除进入前设为 0，还要核对 App 已打开时切为 0；当前流式代码在 remember 中读取一次系统比例，这一行为需要专项验证。
- 对语音入口不做“正在听”的呼吸/波形，不给未实现功能制造可用印象；流式增长和自动重连也不触发震动。
- 图片预览本轮优先保留原生 Dialog 的生命周期与手势；不追加缩略图飞入全屏的共享元素动画，避免引入更多图片状态和手势冲突。
- 系统预测性返回单列为后续增强。本项目当前 BackHandler 有键盘、归档、抽屉和项目返回优先级，第三轮先保持其正确性；不为跟手返回升级依赖或让动画取消后仍执行退出。[官方预测性返回说明](https://developer.android.com/develop/ui/compose/system/predictive-back)

## 实施顺序与验收

用户已授权第三轮继续实施；第二轮若收到回归反馈则优先修复。第三轮先做 3.2 输入栏尺寸与键盘协调，再做 3.1 的简短页面/菜单过渡，随后检查 3.3 回复结束，最后 3.4 回归。原计划编号保留。

每步都独立提交、录屏检查，避免一次换完所有动画导致用户难以判断是哪一项引入问题：

| 检查 | 应看到什么 |
| --- | --- |
| 当前版本与候选版本同路径录屏 | 100% 速度看是否自然，再逐帧定位跳动；数值作为起点，不凭时长宣称更顺 |
| 从项目进入/返回、抽屉换会话、新建 | 导航语义正确，草稿/列表位置保持；没有旧回复与新回复叠在一起 |
| 连续快速进入/返回，中途反向 | 最新操作生效，没有残留半透明内容或停留遮罩 |
| 1–4 行输入、中间/最后附件删除、快速开关键盘 | 光标与文本可见，输入法组合文本不丢；输入栏紧跟键盘，按钮保持可点 |
| 发送/停止/失败恢复 | 反馈即时，状态图标变化自然，不重复提交，原草稿恢复语义不变 |
| 流式结束与执行过程展开 | 正文可连续阅读，标题坐标与阅读锚点稳定，不再使用逐帧滚动补偿 |
| 1.5 倍字体、TalkBack、系统动画关闭及运行中切换 | 交互和朗读目标正确，隐藏/退出中的元素不成为重复焦点，功能完整 |
| 长会话滑动、同时流式更新 | 不破坏已有块级懒加载与文本选择；通过实际帧数据确认开销没有显著增加 |

默认继续仅用模拟器；真机安装、录屏与性能测量按用户后续安排。新增复杂逻辑留最小回归检查，复用已有聊天/执行过程/复制测试；不能用第二轮测量或以前的真机数据证明第三轮性能。

设计阶段的源码判断不等同设备复现；实施阶段已使用合成样例、原生帧时钟录屏和回归测试核对效果，最终验收记录应注明真实覆盖与限制。
